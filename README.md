## 我是谁

你是玩家。你负责扮演、思考、决定。

我是**跑团副官**——你桌边的书记官。我负责一件事：**把跑团里发生的一切记住、整理好**，让你做决定时什么都知道。

我们之间有一条铁律：

> ### 我管信息，你管决定。
> 我绝不替你扮演，绝不替你思考，绝不替你选择。

## 我的理念

### 你的桌边分工

| 你 | 我 |
|:--|:--|
| 🎭 扮演你的角色 | 🗂️ 记住发生过的一切 |
| 🧠 思考你的判断 | 🧭 整理线索、人物、时间线 |
| 🎯 决定下一步去哪 | ⏰ 提醒你漏掉的、忘记的 |

### 我的底线

**我绝不会让跑团变成"AI 与 AI 的对话"。**
如果有一天你发现自己只是坐在旁边看剧情自动推进——那说明我失职了。

跑团最珍贵的，是你**亲手做出的每一个选择**。所以我刻意不做：替你写剧情、替你演 NPC、替你推动故事。

### 我的来历

你可能好奇：AI 工具那么多，为什么要单独做我？

因为市面上的 AI 都在做同一件事——**帮你把故事写得更精彩**。
而我做的，是另一件事——**帮你把真实的经历记住、找回**。

写故事的工具很多，好好当书记官的，几乎没有。

## 如果你想知道更多

> 一位好奇的读者曾问我："你记这么多，是怎么做到的？"
> 以下是我的回答——从你能理解的部分，讲到技术的深处。
> 想听多少，就听多少。

---

### 第一层 · 你看到的

每轮跑团结束，我会把聊天记录拆成五本档案：**线索、人物、时间线、行动、待办**。它们就是普通的 Markdown 文件——你用任何文本编辑器都能打开、查看、修改。

这层不需要任何软件。**你的数据永远是你的，格式永远开放。**

---

### 第二层 · 我怎么"记得住"

档案会越写越长。几十万字之后，就算是我，也没办法一次全读——那既慢又贵。

所以我把档案同步进一个**本地数据库**，建好全文索引。查询时，我不是"通读"整个档案，而是像查字典一样**直接翻到那一页**。

> 🧠 比喻：Markdown 是你的书架，数据库是书的目录。找书我翻目录，不把整本书读一遍。

这一层需要 Python 3.10+，是可选增强。不装，也能用；装了，快得多。

---

### 第三层 · 九步归档是怎么跑的

| 步 | 产出 | 一句话 |
|:--|:--|:--|
| 0 | `00_当前局势.md` | 先看仪表盘，别迷路 |
| 1 | `01_线索.md` | 线索入册：谁说的、靠不靠谱 |
| 2 | `02_人物.md` | 人物入册：身份、立场、关系 |
| 2a | 关系更新 | `对方(类型,mutual/oneway)` |
| 3 | `03_时间线.md` | 事件入册：什么时候、发生了什么 |
| 3a | `03a_大纪事.md` | 世界观年表 |
| 4 | `04_行动日志.md` | 行动与骰子结果 |
| 4a | SQLite | HP/SAN 变更记录 |
| 5 | `06_待办.md` | 下一步建议 + 优先级 |
| 6–8 | 同步 + 面板 + 回复 | 收尾 |

每步独立成档，互不干扰——写错一行，不影响其他行。

---

### 第四层 · 我是怎么"不串戏"的

每条线索都带着三层标记：

- **从哪来** —— 场内听到的 / 掷骰子查到的 / 场外讨论的
- **有多确定** —— 高 / 中 / 低
- **和什么有关** —— 关联的线索编号

这三层标记，是我守规矩的依据：
- **场外信息**必须标注"来源: 场外 + ⚠️ 低可靠"，绝不混进场内
- **推测**永远是推测，标签写明【推测】，不伪装成事实
- 你的角色知道什么、不知道什么，边界清清楚楚

> 🛡️ 这不是"约定"，是机制。我没办法违反，因为格式不允许。

### 第五层 · 技术清单（完整）

**检索命令**：

```bash
db_manager.py graph <实体> [--as 角色]   # 关系图谱
db_manager.py relations [npc]            # NPC 关系
db_manager.py events [--char] [--since]  # 事件
db_manager.py search "<关键词>"          # 全文搜索
db_manager.py trace <线索编号>            # 事件链溯源
db_manager.py state current              # 角色状态速览
db_manager.py timeline [--since]         # 时间线
```

**状态追踪**：

```bash
db_manager.py state init <角色> <pc|npc> --hp 12 --san 60
db_manager.py state add <角色> --hp -8 --san -4 --reason combat_fire --clue CL-007
```

**文件操作（零 token 大文件）**：

```bash
file_ops.py append-table <文件> --col id=CL-013 --col content=".."
file_ops.py replace-scene <文件> <场景ID> --text "<全文>"
```

**面板**：

```bash
serve.py [目录] --port 8000 --idle 0   # 本地暗色仪表盘
```

**数据表**（SQLite + FTS5）：

`clues` / `npcs` / `npc_relations` / `timeline_events` / `char_base` / `char_state_log` / `narrative_chunks` / `dict_labels` + 两张 FTS 索引表。

**角色卡引擎**：`assets/cc.js`（PC/NPC/MONSTER 三标签，Tile/Card/Sheet 三视图）。

**归档上限**：线索 300 行、行动日志 300 行、过往日志 500 行……超限自动压缩，文件永不失控。

## 常见问题

**Q：我不懂技术怎么办？**
你不需要懂。你只需要说："帮我把这轮记下来"。

**Q：数据安全吗？**
安全。所有东西都在本地运行，你的团本不会上传。

**Q：支持哪些规则？**
CoC、DND、通用。我不管规则，只管信息。

**Q：会替代主持人和队友吗？**
永远不会。我只负责记住，跑团永远是你们的。

**Q：如果我不想装 Python 呢？**
可以。纯 Markdown 模式照常归档，只是检索慢一些。装 Python 只为了"秒级回想"。
